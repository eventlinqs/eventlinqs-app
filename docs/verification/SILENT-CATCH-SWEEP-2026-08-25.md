# The silent-failure sweep: every catch block in src/ and scripts/

**Date:** 25 August 2026
**Ordered by:** Lawal Adams
**Guards:** `scripts/guards/no-silent-catch.mjs`, `scripts/guards/no-client-sentry-import.mjs`
**Drills:** 58 of 58 fire, three of them new

---

## The ruling, verbatim

> Tonight's worst finding was a bare catch {} eating a 42703 on a column that has
> never existed, publishing zero venue URLs while nobody noticed. Sweep every
> catch block in src/ and scripts/. Any that swallows an error without logging,
> re-throwing or recording is a defect. Report every one with a verdict, fix
> them, and guard the pattern. Drill it.

---

## What was swept, and how

Not by grep. `scripts/lib/js-source.mjs` strips comments and string literals,
then BRACE-MATCHES every `catch (...) {` to its real closing brace, so a body
containing an object literal, a nested try or a callback is read whole rather
than truncated at the first `}`. It also walks backwards to the matching `{` of
the `try`, because what the catch was guarding is the question that decides
whether its silence matters.

**1,331 files. 728 catch blocks.** Every one adjudicated.

## The verdict, in four classes

| Verdict | Count | What it means |
|---|---|---|
| **SPEAKS** | 531 | Re-throws, logs, reports through the observability seam, or names its binding |
| **SILENT, PURE** | 197 | Catches a parse or a probe. The throw IS the answer |
| **SILENT AROUND I/O** | **135** | **The defect class. All 135 fixed** |
| **EXEMPT** | 8 files | Reviewed, reasoned, printed on every guard run |

### Why "records" means naming the binding

The founder's list is logging, re-throwing, or recording. Recording is read here
as USING THE CAUGHT VALUE: putting it in a returned result, a failures array, a
status field, a message a caller renders. A catch that never mentions its
binding has discarded the error, and a catch with NO binding has discarded it by
construction: there is not even a name by which it could be carried anywhere.
That is exactly `catch {}`, and exactly the sitemap.

### Why the gate is drawn at I/O and not at every catch

336 of the 728 neither log, re-throw, nor name their error. Failing the build on
all 336 would mean an exemption list of roughly two hundred entries, and an
exemption list that long is an inventory rather than a gate: nobody reads it, and
the next real defect is added to it in the commit that introduces it.

A catch around `JSON.parse`, `new URL`, `decodeURIComponent` or `atob` is a
validation. The throw is the expected negative answer to a question the code
asked on purpose, usually about a value a stranger typed, and reporting it would
be noise generated by user input. Those 197 are COUNTED AND PRINTED on every
guard run, so the class stays visible without being enforced.

A catch around a database query, a network call, a filesystem read, a subprocess,
a payment or a mail API is the other thing. When one of those fails there is an
incident, and the silent catch is what decides nobody hears about it.

Every `where` label was RECOMPUTED after the edits landed and audited to 135 of
135 correct. The first pass stamped each report with the line number the catch
had BEFORE the insertion above it moved it, which is a small lie in the one
field whose entire job is to say where.

Nothing was added after a `return`, nothing was removed, and no control flow
changed: the report is inserted as the first statement of the body and the
existing body follows verbatim.

## The one that was reverted, and the guard it produced

`src/lib/launch/bill-ref.ts` was swept in because its try contains
`Buffer.from(...)`, and the detector's Supabase pattern `.from(` matched it. The
catch there guards a base64url decode of a value a stranger can type: a malformed
ref is the expected negative answer, not an incident.

That false positive was one line from a real regression.
`src/components/launch/the-bill.tsx` imports `encodeBillRef` from that file, and
`captureException` comes from `src/lib/observability/sentry.ts`, which statically
imports `@sentry/nextjs`. The header of
`src/lib/observability/client-error-report.ts` records that this exact edge
existed once through the four client error boundaries, put the whole SDK in the
bundle of every route, and that the seam was built to break it. **A comment was
all that had kept it broken.** Nothing in the build would have said a word: the
bundle would simply have been bigger.

So the rule became a gate. `scripts/guards/no-client-sentry-import.mjs` builds
the value-import graph of `src/`, treats `import type` as erased and every
`'use server'` module as a bundle boundary, and fails when any of the 177 client
components reaches the Sentry module.

Getting the boundary right mattered: without it the guard reported 41 violations,
39 of which were server actions reached through a network proxy rather than
through bytes in the browser. A guard that reports 41 findings of which 39 are
wrong is a guard somebody switches off.

## Two things the sweep found on its way past

**A test that was passing vacuously.** `tests/unit/auth/no-silent-auth-failure.test.ts`
asserts that no auth form has a catch that swallows the failure. Its pattern is
`catch\s*\([^)]*\)\s*\{`, which requires a BINDING. `signup-form.tsx` had
`catch {` with none, so the form was never examined at all. Adding the binding
made it visible for the first time, and it turned red. The catch was in fact
correct: it calls `failLocally`, whose body is `setError(...)`. That helper is
now in the test's recogniser, with the reason recorded beside it.

**A reader broken by an apostrophe.** `tests/unit/guards/guard-registry.test.ts`
parses the runner's `GUARDS` array with `/'([^']+)'/g`. A registration comment
written during this work contained the word "guard's", and that single unmatched
apostrophe flipped the quote parity for every entry after it: three of its five
tests went red, naming fragments of English prose as registered guards, while the
runner itself was correct the whole time. It now strips comments before reading,
using the same module the guards use, and `tests/unit/guards/js-source.test.ts`
carries that case as an executable regression.

## The drills

Three added, all firing:

| Drill | Guard |
|---|---|
| the sitemap event query is wrapped in a catch that says nothing | `no-silent-catch` |
| a consent write failure is swallowed and reported to nobody | `no-silent-catch` |
| a module a client component imports starts importing the Sentry SDK | `no-client-sentry-import` |

The first one failed to fire on its first run, and the reason is recorded in the
drill: it removed only the BINDING and left the `console.error`, and a catch that
logs is not silent whatever its binding says. A drill has to remove the voice,
not the name.

## What this guard cannot see, stated rather than implied

- It reads text, not types. `.from(` is how a Supabase query starts and also how
  `Buffer.from` starts, so the built-in forms are excluded by name. That
  exclusion is a list, and a list can be short by one.
- It does not follow a call. A silent catch around `doTheThing()` whose body
  queries the database is invisible to it.
- **It says nothing about the larger silent failure on this platform, which is
  measured here rather than gestured at.** PostgREST does not throw. It returns
  `{ data, error }`, so an error can be discarded with no catch block anywhere
  near it, and this guard cannot see any of it.

  Swept the same way, over `src/`:

  ```
  destructures of an awaited .from() / .rpc()   757
    error carried somewhere with its detail     118
    error named but collapsed to a boolean      142
    error not named at all (data only)          497
  ```

  `src/lib/consent/record.ts` is the shape, four times over, inside the very
  functions this pass just gave a voice to: `const { error } = await admin
  .from(...).upsert(...)` then `return !error`. The caller learns that it failed
  and never learns why, which is one better than the venue block and a long way
  short of enough.

  **That is a separate sweep, it is roughly five times the size of this one, and
  it is named with its number here so it cannot be mistaken for something already
  covered.**
