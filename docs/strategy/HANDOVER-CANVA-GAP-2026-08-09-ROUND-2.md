## WHAT WAS DONE, AND THE TWO THINGS WORTH CARRYING FORWARD

### The parity proof was broken by construction, and that is the lesson

It normalised `/CreationDate` and `/ModDate` with a regex over raw bytes. pdf-lib
writes metadata into a COMPRESSED object stream, so the regex matched nothing and
every render hashed differently regardless of the code. It would have printed
`artwork identical: false` against a byte-for-byte unmodified renderer, so the
handover's instruction that both lines "must print true" could never have been
satisfied.

Freezing the clock fixed it at the source. The hash is now a raw SHA-256 of the
whole file with nothing normalised away, and on that proof the lift IS verbatim.

**Carry this forward:** a proof that has never been run is not evidence, and a
proof that cannot fail is worse than none, because it launders a guess into a
fact. Run it before believing it.

### Looking at the artefact found what every test missed

`npm test` was green on the poster before I opened it. Two real defects were
visible in about ten seconds of looking:

1. A token wider than the line ran straight off the page (a pasted URL).
2. The short-title hole was not gone, only redistributed: "Ruby's 16th" printed
   at the 68pt ceiling on one line centred in a 400pt box.

Both are fixed. The second one matters most, because a short name is the COMMON
case for this surface, not an edge case.

**Carry this forward:** `docs/design/poster-composition/set/` now holds six
posters covering short, medium, long, unspaced-token and two with a real
photograph, regenerated by `npx vitest run tests/unit/poster-visual-set.test.ts`.
Open them. The extension refuses `file://`, so serve the repo on a spare port and
open `http://localhost:PORT/docs/design/poster-composition/set/...` in real
Chrome; headless Chromium has no PDF viewer and shows a blank frame that is a
tooling artefact, not a defect.

### One footgun I created and fixed, worth knowing

`scripts/verify/poster-parity.mjs` originally restored the renderer with
`git checkout -- <file>`, which discards UNCOMMITTED changes. It silently
reverted a fix I had just made, and the only symptom was tests failing again for
no visible reason. It now snapshots the file and restores the snapshot. If you
write a script that swaps a tracked file, never restore it from git.

## THE FOUNDER RULINGS, AS APPLIED

- **R6 honoured.** The ceiling is **3000**, not the 3508 the previous handover
  argues for at length. That argument is now superseded and should not be
  re-litigated from it. The dpi comment is corrected in the same pass: 3000px on
  A4's long edge is about **257dpi, not 300dpi**, and the constant says so.
- **R2 honoured.** No text-scale control was built.
- **R3 honoured.** No colour picker exists; nothing was built that could produce
  something worse than the default.
- **R7 honoured.** Nothing generates an image. The upload renders what the
  organiser supplies; the no-artwork poster composes type.

The 3508 ruling recorded in commit `bbb6992` changed **documentation only** and
no source, so R6 landed on a clean slate rather than needing a revert.

## THE ANSWER TO THE FOUNDER'S QUESTION, FOR THE PART I CAN ANSWER

**Would a promoter look at the poster and think they could not have done better
themselves?**

For the no-artwork poster: **closer, and honestly not yet.** It is now a
deliberate composition rather than a template with a hole, and a short name
fills the page instead of floating in navy. What it still is not is a poster
with a photograph in it, and that is the thing that would make a promoter
forward it to a friend. Which is precisely why Job 4 was sequenced first and why
it being unproven is the headline above.

For the poster WITH artwork: I cannot answer honestly. The artwork composition
is byte-identical to what shipped before (that is the point of the parity
proof), and nobody has yet put a real organiser photograph through the anonymous
path, because the bucket does not exist. Ask again after the migration.

The bottom line is unchanged from the predecessor's honest verdict and should
not be softened: **the gap closes when an organiser's own photograph is on the
poster.** Everything in this session either proved the ground under that or
built the machinery for it. None of it has yet been seen working by a user.
